# Operational runbooks

This directory holds operator procedures for deployment, rollback, secrets, backups, restore, and
clean-room recovery as those capabilities land.

Each runbook states its prerequisites, the exact command, safe expected output, an independent verification, and the recovery path for a partial failure. Commands that can change production name the required GitHub environment approval and never place a secret value on the command line.

Available procedures:

| Runbook                                                                            | Use it for                                                                                                                                                              | Do not use it for                                                                                                   |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| [Bootstrap and verify the management plane](./bootstrap-management-plane.md)       | The one-time project, billing, local-state apply, GCS migration, GitHub environment, IAM, WIF, audit, and broad-access-removal sequence.                                | Routine changes or an agent-run apply.                                                                              |
| [Provision and verify the workload foundation](./provision-workload-foundation.md) | Parent/billing prerequisites, protected inputs, project creation/adoption, private routing, identities, registry, costs, verification, and temporary-access removal.    | Application deployment, a local foundation apply, or execution before its current stop condition is lifted.         |
| [Operate the private PostgreSQL host](./operate-postgresql-host.md)                | Idle-host and database-release verification, isolation, measurements, controlled vertical scaling, disk growth, and image/compute rollback.                             | A local apply, public debugging, schema/data rollback, or production writes before backup and restore checks exist. |
| [Back up and restore PostgreSQL](./backup-and-restore-postgresql.md)               | Four-hour logical backups, daily snapshots, clean restore drills, retention locking, pre-change gates, alert response, RPO/RTO evidence, and PITR thresholds.           | Application rollback, ad hoc object deletion, a public database path, or bypassing protected deployment workflows.  |
| [Deploy and roll back production](./deploy-production.md)                          | Protected release inputs, launch switch, image verification, fixed deployment order, manual initialization, immutable receipts, and whole-app compensation or rollback. | Foundation changes, data restoration, bypassing the reviewed manifest, or direct `gcloud` release changes.          |
| [Configure hosted Plunk SMTP](./configure-hosted-smtp.md)                          | External account ownership, no-branding billing, cost cap, privacy, domain authentication, standard SMTP fields, secret rotation, delivery proof, and provider exit.    | Self-hosting Plunk, storing a credential in code, adding an API/SDK dependency, or changing Authentication.         |
| [Respond to production alerts](./respond-to-alerts.md)                             | Synthetic health, 5xx, job, rotation, database, backup, budget, workflow, channel-verification, and escalation procedures.                                              | Ad hoc production mutation, a second paging stack, payload inspection, or bypassing an owning runbook.              |
| [Recover into a disposable project](./disaster-recovery.md)                        | Temporary recovery authority, exact receipt and backup selection, replacement-project restore, lost-write acknowledgement, verification, and access removal.            | In-place production repair, ordinary application rollback, or a permanent second environment.                       |
| [Archive the legacy infrastructure repository](./archive-legacy-infrastructure.md) | Post-acceptance identity checks, dependency and credential retirement, collaboration drain, Actions disablement, interactive archival, verification, and recovery.      | Archiving before task #277 passes, guessing a renamed target, cloud cleanup, or automated repository mutation.      |
| [Add or rotate a secret version](./secret-versions.md)                             | Hidden double-entry through stdin, numeric-version rollout, disable/re-enable, delayed destruction, and audit.                                                          | Secret container metadata, GitHub secrets, or printing a payload to verify it.                                      |
| [Recover a prior state generation](./state-recovery.md)                            | A corrupt or incorrect live GCS state generation after writers are frozen and recovery is approved.                                                                     | Ordinary application rollback or reconciling resources without a separately reviewed plan.                          |

The root README's [Setup](../../README.md#setup) section links the entry points and repository-only
validation. The PostgreSQL host, release, backup, and disaster-recovery runbooks deliberately
separate compute maintenance, routine rollback, logical data restore, and clean-room rebuilding.
